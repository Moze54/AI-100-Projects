# AI-100-Projects

> **Build 100 Products with AI. Find the Ones Worth Building.**  
> 用 AI 完成 100 个产品，寻找真正值得做的项目。

## 项目简介

这是一个长期进行的 AI 产品实践与探索项目。

我们希望借助 AI 的能力，从真实需求出发，持续发现值得解决的问题，并将有潜力的想法做成**完整、可使用、可部署、可验证商业价值的产品**。

这里的「100 个项目」是一个长期探索目标，而不是一份已经确定、不能更改的开发清单。

目前收集的方向和想法都属于候选池。它们会随着市场变化、用户反馈、技术发展和实际调研持续增加、调整、合并或淘汰。最终是否开发某个项目，以需求验证和综合评估结果为准。

## 我们想做什么

- **发现真实需求**：关注普通用户、内容创作者、开发者和小微商家的实际问题。
- **筛选值得做的产品**：评估用户痛点、市场空间、付费意愿、竞争情况和获客难度。
- **借助 AI 完成开发**：探索 AI 在产品设计、编码、测试、部署和运营中的实际能力。
- **完成真正可用的产品**：不止做 Demo，尽可能形成完整的产品闭环。
- **验证商业价值**：尝试订阅、买断、按量付费、授权等模式，寻找可持续的收入来源。
- **持续复盘**：记录开发成本、遇到的问题、用户反馈和商业验证结果。

## 项目筛选原则

我们不以凑够 100 个项目为目的。一个想法进入正式开发前，应尽可能回答以下问题：

1. **谁会使用？** 目标用户是否明确？
2. **解决什么问题？** 这是高频、刚需、麻烦的问题，还是一个可有可无的功能？
3. **为什么选择它？** 相比现有方案，有什么优势或差异化？
4. **用户为什么付费？** 是否存在清晰的付费理由和付费场景？
5. **市场是否存在？** 是否有竞品、用户讨论、搜索需求或真实交易？
6. **如何获得用户？** 是否有可行的冷启动和获客路径？
7. **能否独立完成？** 是否适合个人或小团队借助 AI 在合理范围内完成？
8. **投入是否可控？** 开发、维护、运营和合规成本是否可接受？

如果调研后发现需求不成立，及时放弃也是项目成果的一部分。

## 什么才算完成一个项目

每个项目根据自身规模确定范围，但原则上不以一个页面或简单 Demo 作为完成标准。一个完整项目通常包含：

- 需求分析与目标用户定义
- 市场调研与竞品分析
- 产品定位、功能范围与交互设计
- UI/UX 设计
- 技术方案、系统架构与数据设计
- 核心功能开发
- 必要的账号、权限、支付等业务能力
- 测试、问题修复与体验优化
- 部署上线与使用说明
- 项目复盘及后续迭代计划

不适用的部分可以根据项目类型删减，不为了形式堆砌功能。

## 商业模式探索

根据产品特点选择合适的商业模式，不预设所有项目都必须采用订阅制。

- 免费增值（Free / Freemium）
- 订阅（月付、年付）
- 一次性买断
- 按次或按量付费
- 积分或套餐
- 企业授权与私有化部署
- 交易服务费或佣金
- 广告及流量变现

价格和模式需要通过竞品研究与用户反馈验证，不把未经验证的估价当作市场结论。

## 项目状态

候选项目会根据进展调整状态：

| 状态 | 说明 |
| --- | --- |
| 待整理 | 刚收集的想法，信息尚不完整 |
| 候选池 | 已记录，等待进一步评估 |
| 调研中 | 正在验证需求、竞品和商业机会 |
| 准备开发 | 通过初步筛选，准备确定范围 |
| 开发中 | 正在设计、编码或测试 |
| 已完成 | 核心功能完成并具备可交付成果 |
| 已上线 | 已部署，用户可以实际使用 |
| 商业验证中 | 正在验证付费意愿、收入和获客 |
| 已暂停 / 已归档 | 暂时停止或经评估后不再推进 |

随着项目推进，仓库将逐步沉淀候选项目、筛选依据、通用规范和实践经验。


每个产品可以在本仓库中独立维护，也可以在条件合适时拆分为独立仓库。本仓库主要负责项目索引、过程记录、通用文档和成果展示。

## 如何参与

欢迎通过 Issue 或 Pull Request 参与：

- 推荐值得解决的真实问题或产品方向
- 补充用户需求、市场数据和竞品信息
- 参与项目调研、设计、开发和测试
- 分享部署、运营、获客和商业化经验
- 对已有项目提出改进建议

提交项目建议时，尽量说明目标用户、具体问题、现有解决方案，以及可能的付费场景。

本仓库中的通用文档、项目索引和实践资料以开源协作为目标。具体产品子项目可能采用不同的许可证，**请以各项目目录或独立仓库中的 LICENSE 为准**。

## 最终目标

完成 100 个有真实使用价值的产品，并从中找到值得长期维护、能够持续服务用户、具备商业可行性的产品。

**不为数量而开发，不为技术而造需求。先找到问题，再把产品做好。**
