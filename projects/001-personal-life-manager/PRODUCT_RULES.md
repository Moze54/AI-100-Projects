# 产品规则与关键业务约束

## 1. 记录与录入
1. 用户不需要先创建个人档案。
2. 所有非必要字段均可跳过。
3. 快速新增优先只要求最少必要信息。
4. 创建后允许补充、编辑和完善资料。
5. 不同资料类型使用适合自身场景的字段。
6. 资料记录与附件是不同的数据对象，附件可独立管理。
7. 删除前说明影响范围；有关联事项时应提示，不擅自删除关联数据。

## 2. 资料、事项和提醒
1. 资料描述相对稳定的信息或文件。
2. 生活事项描述需要在某个时间处理、记住或回顾的事情。
3. 提醒是事项的通知配置，不是另一套重复业务数据。
4. 资料有效期可以关联或生成事项/提醒。
5. 同一事项可以有多个提醒时间。
6. 修改周期事项时，明确区分“仅本次”和“本次及后续”。
7. 完成事项不等于删除事项，应保留必要历史。
8. 事项、资料和资产之间允许双向关联。

## 3. 隐私分级
- 普通：一般待办、普通备注和非敏感生活记录。
- 私密：证件号码、身份资料、健康记录、合同等。
- 高敏感：账号密码、恢复代码、API Key、SSH、数据库凭证等保险箱内容。

不同级别应有不同展示、搜索、通知、导出和解锁策略。隐藏 UI 不能替代安全措施。

## 4. 本地优先
1. 本地是默认存储位置。
2. 不登录也可使用本地核心功能。
3. 不开启云服务时，不上传用户生活资料。
4. 本地数据的创建、查看、编辑和删除不应依赖网络。
5. 用户应能备份、导出和迁移本地数据。
6. 卸载、清除应用数据或设备损坏可能造成数据丢失，产品必须清楚提示并提供备份能力。

## 5. 云同步
1. 云同步必须由用户主动开启。
2. 同步粒度支持模块、分类、单条记录和单个文件。
3. 默认不自动上传；用户明确选择后才纳入同步范围。
4. 父级同步关闭时，子级不得绕过限制上传。
5. “暂停同步”“停止续费”“删除云端副本”“删除本地数据”是不同操作。
6. 客户端加密后再上传，服务端仅保存密文。
7. 服务端不持有解密密钥，不应通过日志、分析事件或错误上报收集明文。
8. 同步失败必须保留本地数据，并提供状态和重试入口。
9. 冲突处理不能静默覆盖用户数据。
10. 设备撤销后，应阻止该设备继续获得新的同步授权；已下载数据如何处理需在安全设计中说明。
11. 删除云端数据应有明确范围、确认、回收站和最终清除策略。
12. 云空间到期不影响本地数据，云端数据取回和宽限期政策需明确。

## 6. 保险箱
1. 保险箱与普通资料具有独立安全边界。
2. 未解锁时不展示敏感字段，不进入普通搜索结果。
3. 通知正文不得包含密码、密钥等明文。
4. 复制敏感内容时提供明确反馈，并评估剪贴板清理能力。
5. 自动锁定时间可配置。
6. 首版默认仅本地保存。
7. 未完成密钥恢复、设备撤销和威胁模型评审前，不开放云同步。

## 7. 提醒
1. 提醒优先由设备本地调度，不依赖服务端推送才能工作。
2. 云同步到其他设备后，由各设备根据授权和设置安排本地提醒。
3. 用户关闭通知权限时，解释影响并提供系统设置入口。
4. 后台策略、设备关机、省电模式和权限状态可能影响提醒送达。
5. 不宣传绝对准时；区分已安排、已触发、已完成和可能错过等状态。

## 8. 健康数据
1. 健康数据默认保持本地，云同步需用户单独明确选择。
2. 健康记录应支持查看、导出和删除。
3. 预测和趋势仅作为记录参考，不构成诊断或治疗建议。
4. 未经明确授权，不将健康数据用于模型训练、广告或个性化营销。

## 9. 删除与恢复
1. 删除前明确说明删除的是本地数据、云端副本还是两者。
2. 删除本地数据不应在用户不知情时自动删除云端副本，反之亦然。
3. 需要回收站的模块应说明保留期限和最终删除时点。
4. 导入、恢复和迁移前应校验文件并提示覆盖范围。
5. 恢复失败不能破坏当前可用数据；原子性和备份策略在技术设计阶段确定。

## 10. 文案与交互
- 使用普通用户能理解的中文，首次出现时解释加密术语。
- 明确区分“本地保存”“已加密上传”“等待同步”“同步失败”。
- 删除、覆盖、云端上传和密钥重置时解释后果。
- 不用恐吓式文案诱导购买云空间。
- 不把云空间付费包装成基础功能会员。
