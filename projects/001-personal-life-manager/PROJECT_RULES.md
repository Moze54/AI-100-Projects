# 拾记项目规范

## 1. 当前阶段边界

当前阶段进行市场调研、产品定义、需求整理、交互规划、安全与技术方案评估。

未经用户明确要求，不得：
- 创建业务代码或初始化应用工程。
- 安装依赖、生成构建配置或部署服务。
- 擅自确定客户端、服务端技术栈和云服务商。
- 将待研究事项写成已确定需求。
- 把所有已确认功能默认解释为首发版本一次性交付。

## 2. 需求状态

- **已确认**：用户明确选择或确认的产品方向和规则。
- **待研究/待设计**：还需要调研、评审、成本测算或交互设计。
- **明确不做**：用户明确排除的范围，不进入功能清单和待开发列表。
- **已废弃**：曾讨论但已被新决策替代的方案。

建议和技术推断不得标记为已确认。

## 3. 产品设计原则

- 拾记定位为个人信息收纳与个人生活管理的结合。
- 以真实生活场景为起点，不为堆功能而堆功能。
- 快速录入优先，非必要字段允许跳过。
- 本地优先、隐私优先、用户可控。
- 登录需要联网，但普通资料默认本地保存，不因登录自动上传。
- 普通资料与保险箱必须有清晰安全边界。
- 同一账号可多设备登录；单设备同一时间只允许一个账号。
- Windows 与 Android 同步开发、同步发布；iOS 二期。
- Web 仅作为管理员后台。
- 固定 4 Tab：首页、资料、日历、我的。

## 4. 文档规范

- 使用 Markdown，产品文档使用中文。
- 每份文档标明版本、状态和更新时间。
- FEATURE_LIST.md 只记录已确认纳入产品范围的功能，不用 P0/P1/P2 擅自确定首发排序。
- DECISIONS.md 维护已确认、待研究和明确不做事项。
- 需求变化时同步更新 PRD、功能清单、产品规则、决策记录和路线图。
- 不在多份文档维护互相矛盾的功能状态。
- 待研究事项不等于待开发功能；明确不做事项不进入开发清单。

## 5. 安全与隐私

- 不提交真实用户资料、证件图片、账号密码、密钥、令牌或生产数据。
- 示例数据必须虚构。
- 不把密码、密钥、证件内容或健康内容写入日志、错误信息和分析事件。
- 普通用户数据采用端到端加密方向，服务端不持有解密密钥。
- 保险箱采用独立主密码和恢复密钥体系。
- 不自行设计密码学算法或协议；采用成熟标准、经过审查的库和专业安全评审。
- 端到端加密不代表免除平台隐私和数据保护义务。
- 健康、证件和保险箱数据按敏感程度进行保护。
- 未经用户明确选择，不上传普通资料。

## 6. 功能验收

每个进入开发的功能至少明确：
- 用户目标与使用场景。
- 前置条件和权限要求。
- 正常流程。
- 空状态、错误状态和边界情况。
- 数据创建、修改、删除、恢复和版本行为。
- 本地/云端存储及同步行为。
- 隐私、安全和可验证的验收标准。

## 7. 范围与交付

- 产品功能范围已确认，不等于首发顺序已确定。
- 首发范围必须结合市场研究、用户验证、成本和依赖进行冻结。
- 涉及端到端加密、密钥恢复、设备撤销、冲突处理和云端删除的功能，安全方案未评审前不得进入正式实现。
- 新增需求说明价值、成本、风险和对现有范围的影响。
